# Contributing

Thank you for your interest in this project. Please read through this document
before opening an issue, as it explains how contributions are handled here.

## Project Governance

This project currently has a single maintainer, and there are no plans to add
additional maintainers in the near future. As such, decisions about what gets
accepted, rejected, or prioritized are made at the maintainer's sole discretion,
based on their own judgment and experience as a software engineer. This is not a
democratic or community-governed project, and this is stated upfront so
expectations are clear from the start.

## How to Contribute

The only accepted channel for contributions is **GitHub Issues**. Contributors
are welcome to:

- Report bugs
- Suggest features or improvements
- Share feedback or criticism about the project

All input is genuinely welcome, and the time anyone takes to engage with the
project is appreciated.

## What to Expect

To set expectations clearly:

- There is **no guaranteed response time or ETA** for replies to issues.
- There is **no guarantee** that any issue will receive a response at all.
- There is **no guarantee** that feedback, suggestions, or criticism will be
  accepted or acted upon, regardless of how it is received.

Every issue is read and considered, but the final decision on whether to act on
it rests with the maintainer.

## A Note on AI-Generated Feedback

Please do not submit feedback that consists of output copy-pasted from an AI
coding agent (e.g. asking an LLM to review or critique the repository and
pasting the result into an issue). The maintainer is fully capable of running
that kind of analysis locally, and this kind of submission adds no value while
consuming review time. Issues that are clearly unfiltered AI output without
personal review or context may be closed without response.

Thoughtful, personal feedback — even if informed or assisted by AI tools — is of
course still welcome, provided it reflects the contributor's own understanding
and judgment.
